# email-lists

Three files that decide which email domains C.H.A.T. will send a sign-in link
to. Deployed to the application's **private** configuration area, outside
`public_html`, and readable only by the application.

```text
disposable-domains.txt   generated — the cached upstream registry
allowlist.txt            local override: always accept
blocklist.txt            local override: always refuse
```

`disposable-domains.txt` is **not** in version control: it is generated by the
updater and refreshed independently of the application's source. The two
override files are, because they are decisions this application has made.

## Deploying

Copy this folder to the private area and point the application at it:

```dotenv
EMAIL_DOMAIN_LIST_DIR=/home/…/private/chat_app/email-lists
```

Then populate the registry:

```bash
npm run email:update-registry --workspace api
```

Nothing fetches anything while somebody is signing in. The registry is a local
cache; if GitHub is unreachable, authentication carries on using the copy
already on disk.

## Precedence

```text
allowlist.txt  → accept, whatever else says
blocklist.txt  → refuse
disposable-domains.txt → refuse
otherwise      → carry on to the DNS check
```

The allowlist is first on purpose: upstream registries misclassify real
organisations, and when that happens somebody needs to fix it in a file rather
than in a deployment. It bypasses **domain reputation only** — an allowlisted
address still passes syntax, DNS, rate limits and the magic link itself.

## Format

One domain per line, lowercase, `#` for comments. Blank lines and duplicates
are ignored, and a line that is not a usable domain is skipped rather than
failing the whole file. Never put a complete email address in these files.

## Source

`disposable-domains.txt` is generated from
[groundcat/disposable-email-domain-list](https://github.com/groundcat/disposable-email-domain-list)
(MIT), which validates its entries against MX records. The generated file
records its source, the time it was written and how many domains it holds.

A failed update never replaces a working registry. See
`api/src/auth/registry-update.ts`.
